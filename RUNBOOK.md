## Election day
- 6:00 pm ET: enable the `Update results` workflow (or start `Rscript R/watch.R 120` on a laptop with push access). Check the Actions tab shows a green run.
- 7:00 pm ET: Volusia County (Edgewater) opens. 7:30 pm: all 19 Ohio measures. 8:00 pm: Kansas (3), Illinois (7), Chester County PA. 9:00 pm: Rock County WI. 10:00 pm: Clark County NV. 11:00 pm: LA County CA.
- As each county's first numbers post, open its page and compare to the dashboard card. If the card still says "No results yet":
  1. Look at the Action log (or `watch.R` output) for that `race_id`. "no contest matched" means the `contest_pattern` regex is wrong: copy the exact contest name from the page into `sources.csv`. "could not map choices" means the choice labels are not Yes/No: set `yes_pattern` / `no_pattern`.
  2. If the page is a PDF, switch `adapter` to `pdf` and put the PDF URL in `api_url`.
  3. If nothing works within a few minutes, key the numbers into the Google Sheet with `override = TRUE`. Manual beats automated. Keep updating that row as the county updates.
- **Ohio drop folder (17 sources on `boe.ohio.gov`, `huron.boe.ohio.gov`, `liveresults.boe.ohio.gov` and Franklin's ENR).** These hosts block every script, so the pipeline never requests them. Instead:
  1. Run `make drop`. It lists each county page to open and which races have no file yet.
  2. Open the page in your normal browser and save the **cumulative or summary** results into `~/Downloads/dcbt_drop` (or `$DCBT_DROP_DIR`). Save PDFs as they come; save ENR pages (Butler, Lucas, Franklin) with File > Save Page As > "Webpage, Complete". Any filename works: the pipeline matches files to races by the contest text inside them and reads the newest match. Files named with "precinct" or "detail" are ignored.
  3. Repeat whenever a county posts an update. The loop picks it up on its next pass, and the result's `as_of` is the file's download time, not the fetch time.
  - Only files modified on or after Nov 3 are read (`DCBT_DROP_SINCE` overrides). GitHub Actions has no drop folder, so these 17 sources only update from the Mac loop.
  - Still replace the `ELECTION_ID` placeholders for the three ENR counties so the dashboard's source link works.
  - The ENR folders (`liveresults.boe.ohio.gov/ENR/butlerohenr/` and the like) answer "Forbidden" on their own; open the election's page, `…/<id>/en/Index_<id>.html`, from the county board's results link. Known ids: Butler May 2026 = 23 (Nov 2026 probably 24), Lucas Nov 2025 = 21 (May 2026 probably 22). Franklin: follow https://vote.franklincountyohio.gov/election-info/2026.
  - Formats checked against May 5, 2026 files (fixtures in `R/tests/testthat/fixtures/`): Ashtabula, Defiance, Licking, Pickaway and Wyandot (Electionware) and Champaign and Clinton (Hart) are text PDFs the reader handles. **Huron posts a scanned image** even on election night (its May unofficial canvass, timestamped 9:32 pm), so Monroeville needs manual entry in the sheet. Adams's May file online is a scanned official canvass; whether its election-night PDF is text is unknown, so be ready to enter Sprigg and Monroe by hand.
- Mark a race `status = final` in the sheet once the county shows 100% precincts or "final unofficial".
- Use the **Copy summary** button for a plain-text update to paste into email or Slack.

## Known soft spots
- Ohio SOS `liveresults.ohiosos.gov` carries statewide contests and State Issue 3 only (Directives 2026-22 and 2026-48; the Nov 2025 SOS review sent readers to county sites for local results). All 20 Ohio measures come from 15 county boards: Butler, Franklin and Lucas run an ENR site whose instance ID changes each election (read it off the index page at 7:30 pm); the other 12 post PDFs.
- Election IDs and night-of PDF links are found automatically: each pass reads the page in `discover_url` (`data/sources.csv`) and fills `ELECTION_ID` or `PDF_URL`, logging "discovered ELECTION_ID = …" once. Covered: Bloomington and Madison (Clarity), Will (Clarity, if the county uses it), Morgan IL (GBS), LA County (walks ids 4339–4370), Volusia, Trumbull (Hubbard) and Delaware (Sunbury) PDFs. A source still waiting logs "ELECTION_ID not discovered yet" and makes no request. If a rule misses, paste the id or url over the placeholder in `sources.csv` (that wins), or fix `discover_pattern`. Found values are cached in `data/discovered.json`; delete a line there to force a fresh look.
- Clarity usually lists an election a few days early with zero counts. Once Bloomington and Madison appear, run `Rscript R/fetch_results.R --dry-run` and check the logged contest names match the patterns.
- The Butler, Franklin and Lucas ENR urls still carry `ELECTION_ID`, but those counties come through the drop folder; replace the id only so the dashboard's source link works.
- Illinois: Bloomington's numbers come from the Bloomington Election Commission, not McLean County.
- Wisconsin: Janesville absentee ballots are counted centrally and may post separately from in-person totals.
- Kansas counties post PDFs; the `pdf` adapter is best-effort. Plan on manual entry for Emporia, El Dorado and Ottawa.
- GitHub's 5-minute cron can lag by 10–20 minutes on busy nights. `R/watch.R` is the fallback.
- "Votes remaining" assumes equal-size precincts. Say "estimate" if you quote it.

## After
- Disable the cron workflow. Run `make fetch` once the next morning for complete unofficial counts, set `final` on everything, and commit.
